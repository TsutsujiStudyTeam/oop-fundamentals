# 第5章: 小粒クラス

## 核心となる考え
数量・金額・日付・氏名のような**粒度が非常に小さいクラス（小粒クラス）**を見逃すと、文字列編集や消費税計算が関数として散らばり、きれいな設計ができない。小粒クラスは他クラスの属性として使われる前提で極めて汎用的に設計し、システムや時代をまたいで再利用する。

## 導入されるフレームワーク
- **小粒クラスの定義と代表例**
  - 他のクラスの属性として使われることを前提とした、粒度の極めて小さいクラス。
  - 例: 数量、金額、日付、氏名、宛先、クレジットカード番号、電話番号。
  - 設計方針: 極めて汎用的に。一度作ればシステムや時代をまたがって再利用できる。
- **数値系クラス群（業務システムで最も使う）**
  | クラス | 属性 | 主なメソッド | 備考 |
  |---|---|---|---|
  | 数値（最上位） | 数値（十進数=BigDecimal）、整数部桁数、小数部桁数 | 足す／引く、カンマ区切りで返す | 文字列編集関数を別途用意する必要がなくなる |
  | 数量 | 数値 + 単位 | 単位付きの文字列を返す（"3個", "10kg", "43坪"） | デフォルト単位は「個」が便利。単位もクラス化することがある |
  | 金額（abstract） | 通貨 | 通貨記号付きカンマ区切りで返す（"$123,456,789"） | 様々な通貨の金額を汎化。アプリは円貨金額／外貨金額を直接使う |
  | 円貨金額 | 内/外税区分（内税／外税／税自身） | 消費税額を返す(日付) | 日本特有の処理。消費税計算関数を別途作る必要がなくなる |
  | 外貨金額 | 通貨 | 円貨金額に変換する(日付) | 通貨の「レートを返す」を利用。金額発生日付が必要 |
  | 通貨（※数値系ではない） | ISOコード、通貨記号、自国通貨フラグ | レートを返す(日付) | レート一覧を持つ |
  | レート | レート値、レート日付 | | 日付によって変わる |
  | レート一覧（一山クラス） | 複数のレート | レートを返す(日付, 自国通貨フラグ) | 自国通貨のレートは常に「1」の特殊処理 |
  | 消費税率 | 税率値（5 か 0.05 かは設計者判断） | | 持ち方に合わせて円貨金額側を実装 |
  | 消費税率一覧（一山クラス、static） | 複数の消費税率 | 該当日の消費税率を返す(日付) | 税率は日付で異なる |
  - 継承関係: 数値 ← 金額 ← 円貨金額／外貨金額、数値 ← 数量／レート／消費税率。（注: 原典のクラス図には `数値 <|-- 通貨` も描かれているが、本文は2度「通貨は数値系クラスではない」と明記しており図と矛盾する。本スキルは本文側を採用。）
  - 日本国内前提なら円貨金額の通貨は明示保存しない → 金額ではなく**外貨金額が通貨を持つ**設計にするとよい。FX取引など全通貨相互変換が必要なら円貨／外貨を区別しないモデルにする。
- **日付クラス（物クラス）**
  - 暦としてあらかじめ定義されている特定の日を表すので物クラス（「営業日マスタ」をイメージ）。「2011年8月17日の売上金額」と「2011年8月17日の契約件数」は同じ日付オブジェクトを指す。
  - 内部は java.util.Calendar など。グローバルシステムならロケールも意識。
  - メソッド例: ハイフン／スラッシュで区切った文字列を返す、翌日／翌月／翌年の日付を返す、xx日後の日付を返す（会計のサイト計算用）。
- **体積クラス（結果クラスの小粒例）**: 長さ・幅・高さを持ち、3者を乗算して体積を返す。物流で出荷荷姿ごとに体積管理が必要だったために設計。

## 重要概念
- **小粒クラス**: 他クラスの属性として使われる、粒度が極めて小さいクラス。
- **一山クラス**: 同じものを複数持つクラス（レート一覧、消費税率一覧）。→ 第6章。
- **内/外税区分**: 内税／外税／税自身（消費税額自身を持つインスタンス）の3値。
- **自国通貨フラグ**: 自国通貨のレートが常に1であることを扱うための属性。

## メンタルモデル
- 「文字列編集の関数を作りたい」と思ったら、その文字列が表す業務概念（氏名、住所、日付、金額）の小粒クラスを見逃していないか疑う。
- 「〜を計算する関数」（消費税額、換算額、体積）は、計算に必要な属性を持つ小粒クラスのメソッドにできる。
- 値が日付で変わるもの（レート、税率）は「値クラス + 一覧クラス（一山）」の対で設計し、一覧クラスに「日付で該当値を返す」を持たせる。

## アンチパターン
- **文字列で表される小粒クラスの見逃し**: 氏名、住所は特に見逃されがち。結果として関数頼みの実装になる。
- **BigDecimal や Calendar を生で属性に持つ**（派生: 原典の「数値クラスが内部でBigDecimalを利用し編集・演算を持つ」からの推論）: 桁数・単位・通貨・税区分という業務情報を持てず、編集・演算処理が各所に散る。
- **O/Rマッパの制限に合わせて小粒クラスを諦める**: 複数カラム→1クラスのマッピングや自作クラスのマッピングができない場合でも、マッピングを自前でコーディングして小粒クラスを使う。保守性が格段に上がる。

## 図: 日本国内向けの金額まわり
```text
外貨金額 "0..*" → "1" 通貨 "1" → "1" レート一覧 "1" → "1..*" レート
  + 円貨金額に変換する(): 円貨金額        + レートを返す(日付, 自国通貨フラグ): レート
円貨金額 "0..*" → "1" 消費税率一覧 "1" → "1..*" 消費税率
  + 消費税額を返す(日付): 円貨金額        + 該当日の消費税率を返す(日付): 消費税率
```
- **示していること**: 「日付で値が変わる」概念は一覧クラスが日付をキーに値を返す。計算処理は金額クラス側に閉じる。

## 具体例（ワーク）
**消費税額の計算を関数にしない**（派生: 原典の第5章と第7章の関数例 `getSalesTax` を組み合わせて再構成したシナリオ。破綻の描写は原典にはない）:
- 関数版（禁止）: `getSalesTax(BigDecimal amount)` が税率5を固定で持ち、呼び出し元が内税／外税を判断する → 税率改定時・内外税混在時に呼び出し箇所すべてを修正。
- 小粒クラス版: `円貨金額.消費税額を返す(日付)` が、自身の内/外税区分と消費税率一覧から該当日の税率を得て計算。税率改定は消費税率一覧にレコード追加のみ。呼び出し側修正ゼロ。

## 要点
1. 他のクラスの属性として利用されるのが小粒クラス。代表は数量・金額・日付。
2. 数値系は「数値」を最上位に、数量／金額／レート／税率を継承で展開する。
3. 金額は通貨を持ち、円貨金額は消費税、外貨金額は円貨換算というメソッドを持つ。計算関数を別に作らない。
4. 日付で変わる値（レート・税率）は「一覧クラス」が日付で該当値を返す。
5. 日付クラスは物クラス。編集・日付演算メソッドを汎用的に揃える。
6. O/Rマッパの制限があっても、自前マッピングで小粒クラスを使う。

## 関連
- **第4章**: 小粒クラスの多くは物クラス（日付、氏名）、一部は結果クラス（金額、体積）。
- **第6章**: レート一覧・消費税率一覧は「一山クラス」。
- **第8章**: 氏名クラスを見逃すと private メソッドが欲しくなる。
- **第9章**: 小粒クラスからのみ文字列編集関数を使う運用規則。
