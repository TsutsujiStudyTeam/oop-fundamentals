# 第11章: 業務シナリオで考える

## 核心となる考え
業務モデルは**オブジェクト図 → 分析クラス図 → 設計クラス図 → シーケンス図**の順に作る。実例（オブジェクト図）から始め、分析段階で**一山クラス（一覧系）と小粒クラス**を見逃さなければ、従来の正規化手法の延長線上で難しくない。

## 導入されるフレームワーク
- **モデリング手順**
  1. **オブジェクト図**: 何はともあれ業務分析はここから。コツは**複数ありうるオブジェクトは必ず複数描く**（入荷伝票2枚、商品複数）。
  2. **分析クラス図**: クラス名だけ。第4章を参考に物・結果クラスを抽出。画面・帳票は各1クラスで省略設計可。
  3. **設計クラス図**: 属性と処理を記述して洗練。出力したい帳票・画面を前提に処理を定義する。
  4. **シーケンス図**: 設計クラス図のメソッドを組み合わせる。クラス図のメソッド不足を確認する補足手段なので、全シーケンス図を描く必要はない。慣れないうちは両者を行ったり来たりしてよい。
- **分析で見落としがちな3点**
  1. 採番する際に**伝票番号一覧**（static、最近採番値を持つ）が必要。
  2. **伝票入荷状態**（未入荷／一部入荷／入荷済）と**明細入荷状態**（未入荷／入荷済）は異なるクラス。
  3. **入荷明細一覧画面は入荷伝票ではなく入荷明細一覧を扱う**。伝票に関係なく明細を一覧表示するので、入荷明細一覧クラスがないと一覧データ構造への処理が分散する。
- **一覧系クラスの必須メソッド**: 「次の明細を返す()」「次の伝票を返す()」。GoFの Iterator パターンと同様（「次の明細は存在するか」も本来必要、ここでは省略）。
- **小粒クラスの表示メソッド**: 日付.日付の文字列を返す()（"2012年03月02日"）、個数.単位付きの個数を返す()（"123個"）。帳票だけでなく画面・バッチでも利用する。

## 重要概念
- **オブジェクト図**: 具体的インスタンスの図。分析の出発点。
- **分析クラス図**: クラス名と関連のみ。
- **設計クラス図**: 属性・メソッドまで記述。
- **伝票番号一覧**: 採番のための一山クラス（static）。
- **伝票入荷状態／明細入荷状態**: 値域が異なる別クラス。

## メンタルモデル
- 要件文を読んだら、まず具体的な伝票を2枚、脳内で記入してみる（オブジェクト図）。
- 「〜一覧画面」「〜一覧帳票」が要件にあれば、対応する「〜一覧クラス」が分析クラス図にあるか確認する。
- 状態区分は「何の状態か」ごとに別クラス。原典は伝票入荷状態（未入荷/一部入荷/入荷済）と明細入荷状態（未入荷/入荷済）を異なるクラスと明記しており、要件上の値域の差からもそう読める。
- シーケンス図を描いていて「このメソッドがない」と気づいたら設計クラス図に戻って追加する。

## アンチパターン
- **要件から直接クラス図を描く**: 実例を経ないと一山クラスや明細を見落とす。
- **オブジェクト図に1インスタンスしか描かない**: 複数性（一覧の必要性）が見えない。
- **ヘッダの状態と明細の状態を同じクラスにする**: 値域が違う。
- **明細一覧画面に入荷伝票一覧を渡して画面側で明細を展開する**: 一覧処理の分散。

## 具体例（ワーク）: 入荷予定伝票システム
**要件**: 入荷予定伝票（伝票番号、入荷予定日、仕入元会社、入荷状態[未入荷/一部入荷/入荷済]、複数明細[商品名、個数]）。商品ごとに入荷日・入荷状態[未入荷/入荷済]を持ち、分納可能。機能: 全伝票の検索一覧画面、伝票登録画面、ある日に届いた商品の全明細表示画面、同帳票。

**オブジェクト図**: 「2012年1月5日A社入荷予定」(No.2012010501, 一部入荷) → 商品E 5個 入荷済 1/5、商品M 8個 未入荷。「2012年1月6日B社入荷予定」(No.2012010602, 一部入荷) → 商品G 3個 入荷済、商品M 6個 未入荷。

**分析クラス図（クラス名）**: 入荷伝票一覧画面、入荷伝票登録画面、伝票番号一覧(static)、入荷伝票一覧、入荷伝票、伝票番号、仕入先会社、伝票入荷状態、日付、入荷明細一覧画面、入荷明細一覧帳票、入荷明細一覧、入荷明細、商品、個数、明細入荷状態。
主な関連: 入荷伝票一覧 "1"→"0..*" 入荷伝票 "1"→"1..*" 入荷明細 "0..*"→"1" 商品／個数／明細入荷状態／日付(入荷日)。入荷明細一覧 "1"→"0..*" 入荷明細。入荷明細一覧画面・帳票 → 入荷明細一覧。

**設計クラス図（抜粋）**:
| クラス | 属性 | メソッド |
|---|---|---|
| 伝票番号一覧 (static) | 最近採番値: int | + 伝票番号を採番する(): 伝票番号 |
| 入荷伝票一覧 | | + 次の伝票を返す(): 入荷伝票 |
| 入荷伝票 | | + 伝票番号を返す(), + 入荷状態を返す(), + 入荷予定日を返す(), + 仕入先会社を返す(), + 次の明細を返す() |
| 入荷明細一覧 | | + 次の明細を返す(): 入荷明細, + 指定日付の明細を取得する(日付) |
| 入荷明細 | | + 商品を返す(), + 個数を返す(), + 入荷日を返す(), + 明細入荷状態を返す(), **+ 入荷伝票を返す()** |
| 日付 | 年, 月, 日 | + 日付の文字列を返す() |
| 個数 | 個数値: int | + 単位付きの個数を返す() |

**帳票「2012年02月15日入荷の明細一覧」**（列: 伝票番号 / 仕入先会社 / 入荷予定日 / 商品 / 数量）のシーケンス:
```text
入荷明細一覧帳票 → 入荷明細一覧.指定日付の明細を取得する(日付)
               → 日付.日付の文字列を返す()  → 帳票見出しを出力
  [loop 明細ごと]
   → 入荷明細一覧.次の明細を返す(): 入荷明細
   → 入荷明細.入荷伝票を返す() → 入荷伝票.伝票番号を返す() → 伝票番号.伝票番号文字列を返す() → 出力
   → 入荷伝票.仕入先会社を返す() → 仕入先会社.仕入先会社名を返す() → 出力
   → 入荷伝票.入荷予定日を返す() → 日付.日付の文字列を返す() → 出力
   → 入荷明細.商品を返す() → 商品.商品名を返す() → 出力
   → 入荷明細.個数を返す() → 個数.単位付きの個数を返す() → 出力
```
ポイント: 明細から伝票情報（番号、仕入先、予定日）を得るために入荷明細が「入荷伝票を返す()」を持つ。帳票は入荷伝票一覧ではなく入荷明細一覧を起点にする。

## 要点
1. 業務モデルを作成する際にはまず実例を考える（オブジェクト図）。複数ありうるものは複数描く。
2. 分析段階から一山クラス（一覧系クラス）を忘れない。
3. 一覧画面・帳票は対応する一覧クラスを扱う。伝票経由で明細を展開しない。
4. 状態区分は対象ごとに別クラス。採番には番号一覧クラス。
5. 一覧クラスには Iterator 相当の「次の〜を返す()」を持たせる。
6. シーケンス図はクラス図のメソッド不足を検証する道具。全部描く必要はない。
