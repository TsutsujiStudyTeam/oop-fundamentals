# 第14章（参考資料）: What Is an Object?（The Java™ Tutorials）

> 本書が「クラスとはデータ構造」「privateメソッド禁止」の根拠として引用する Oracle Java Tutorials のページ。著者自身の文章ではなく出典資料。

## 核心となる考え
ソフトウェアオブジェクトは現実世界のオブジェクトと同様に**状態（state）と振る舞い（behavior）**から成る。状態は**フィールド**に保持し、振る舞いは**メソッド**で公開する。内部状態を隠し、すべてのやりとりをメソッド経由にすることが**データカプセル化**であり、OOの基本原則。

## 導入されるフレームワーク
- **状態と振る舞いの観察法**: 身の回りのオブジェクトごとに「取りうる状態は何か?」「取りうる振る舞いは何か?」の2つを問い、書き出す。犬（名前、色、品種、空腹／吠える、取ってくる、尻尾を振る）、自転車（現在のギア、ケイデンス、速度／ギア変更、ケイデンス変更、ブレーキ）。オブジェクトは複雑さが異なり（ランプは状態2つ、ラジオは多数）、他のオブジェクトを含むこともある。
- **同心円モデル**: 中心にフィールド（状態）、外周にメソッド（振る舞い）。メソッドは内部状態を操作し、オブジェクト間通信の主要手段となる。
- **自転車オブジェクト**: 状態（速度、ケイデンス、ギア）と、それを変更するメソッドを持つことで、外部からの使われ方をオブジェクト自身が制御する。ギアが6段なら、1未満や6超を拒否するメソッドにできる。
- **オブジェクト化の4つの利点**
  | 利点 | 内容 |
  |---|---|
  | モジュール性 | オブジェクトのソースは他と独立して書け、保守できる。システム内で容易に受け渡せる |
  | 情報隠蔽 | メソッドとだけやりとりするので内部実装の詳細は外部から隠れる |
  | コード再利用 | 既存オブジェクト（他者作成含む）をそのまま使える。専門家が実装・テストした複雑なオブジェクトを信頼して利用できる |
  | 差し替え容易性とデバッグ容易性 | 問題のあるオブジェクトを取り外して別のものを差し込める。ボルトが折れたらボルトだけ替えるのと同じ |

## 重要概念
- **state（状態）／fields**: オブジェクトが持つデータ。本書の「データ構造」。
- **behavior（振る舞い）／methods**: 状態を操作する処理。
- **data encapsulation（データカプセル化）**: 内部状態を隠し、メソッド経由でのみ操作させること。

## 本書との接続
- 本書第2章: 「Fieldsというのがデータ構造のことで、その周りを処理（Methods）が取り巻いている」→ データ構造を持たないクラスは機能しない。
- 本書第8章: 「フィールドを隠蔽するためにメソッドが口を開けている」→ 隠蔽すべきはフィールドであってメソッドではない → privateメソッド不要。
- 本書第4章: 「状態はデータ構造によって規定される」「どんな状態を持つ必要があるか」を追求せよ。

## 要点
1. オブジェクト = 状態（フィールド）+ 振る舞い（メソッド）。
2. 内部状態を隠し、メソッドだけを公開するのがデータカプセル化。
3. メソッドは状態を守るための窓口（不正なギア値を拒否する等）。
4. 利点はモジュール性、情報隠蔽、再利用、差し替え容易性。
